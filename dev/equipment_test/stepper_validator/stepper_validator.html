Stepper Motor Validator

Needs the Web Serial API: use Chrome or Edge (not Firefox or Safari). Opening this file directly (file://) works. If your browser refuses, serve it with python3 -m http.server and open http://localhost:8000/stepper_validator.html.

Esc = emergency stop (ESTOP: halts and disables the driver). The firmware never moves on its own; the page keeps a 250 ms STATUS heartbeat and the firmware stops if it stops arriving.

Soft limit: the most this axis may travel from LS1, for a probe that cannot reach LS2 (axis 1). Set it with the drive disabled; it is kept on the board. It holds once the axis has touched LS1 since power-up: until then only the jog buttons move it (jog onto LS1 first). Nothing then passes the limit; a Move past it stops on it.

Distances in mm, speeds in mm/s (1 motor rev = 1 mm on this stage). Step resolution only sets the size of one commanded step: the driver interpolates every setting to 1/256, so smoothness, torque and heat do not change. Fine resolutions lower the top speed (step-rate ceiling). The firmware clamps values, replies with what it applied, and these fields follow its replies.

Motion

Hold to jog (sends JOG every 100 ms; release stops it).

Tests

Run in order: UART, COILS, REVS, SWEEP, LIMITS. All but UART need the driver enabled and both limit switches clear. LIMITS drives to each switch at 1 mm/s: watch the first run and press Esc if the carriage reaches an end without stopping. Running: none

LS1/LS2 show TRIPPED or clear, and the end each guards once learned (+ or −, from its first trip while moving). Both TRIPPED at centre under NC means normally-open switches or an open circuit (cable, GND); NO shows both as clear, so press each switch and see it read TRIPPED before trusting it. Home level is the raw Vo pin (bare phototransistor: 0 slot clear, 1 blocked or no signal): block the slot and see it change. ola/olb are only meaningful while moving in spreadCycle. reset = 1 after boot means the driver lost power or reset (check VM and VIO).
