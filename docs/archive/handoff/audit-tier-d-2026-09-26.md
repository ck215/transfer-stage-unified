## Bench-visible tonight (the c rows, in priority order)

1. **D4**: swapping the gamepad in Manual mode keeps the motors energized and manual jogging live on the new pad. Nothing stops, and nothing tells the operator.
2. **D5**: if a jog write fails (a USB hiccup or cable pull), the probe goes to FAULT without sending a stop. The firmware keeps running the last velocity packet, so the stage can drift. FULL STOP then reports "not confirmed", because the port handle is already closed. Recovery is closing the device in the rail and reopening it, or Relaunch.
3. **D2**: rotator Move or Home can report finished while the stage is still turning (the poll and the move read each other's replies). Worst around 20 ms reply latency.
4. **D6**: pressing Refresh after Launch reopens the ports the running probes hold, at other baud rates. On macOS or Linux the running board receives the identity query and `s` bytes, and its link can be left at the wrong baud until Relaunch. On Windows it shows a port warning instead.
5. **D14**: in Manual mode, Manual Speed and the step sizes are greyed out or refused. Changing them means leaving Manual, which de-energizes the coils.
6. **D11**: rotator Step reads 0 at launch, so Move +/- does nothing and says nothing.
7. **D8**: the heater refuses settings main accepted (for example 250.5, 120, 12.25, 0.25, .05, -1.5 gives "33 characters is more than the 31"), and the message does not name the field to shorten.
8. **D9**: Reset Baseline mid-run overwrites the run's starting baseline, and Tk Save copies only the CSV, not the sidecar.
9. **D10**: the T.16000M throttle buttons drive Z at full ±1 (main used ±0.5); the stick deadzone is 0.12 (main's T.16000M hotfix used 0.03); the first 5 % of trigger travel is dead.
10. **D7**: a Rotator on a bad port blocks the whole launch, so the probes and heater do not start either.
11. **D12**: firmware auto-detect finds no ports on Windows, and there are no flash launchers.
