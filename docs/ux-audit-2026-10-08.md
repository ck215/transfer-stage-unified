## Findings

### 1. Dashboard tiles with a store prompt grow without end (P1, Fixed 904194a)

Evidence: `SHOTS/b02-dashboard-full-L.png` (page 6229 px tall),
`SHOTS/c-dash-full-L.png`; `c.log`: the Transfer Map and Sample DB tiles went
17, 21, 25, 29, 33, 37 grid rows in five seconds (1872 to 4112 px) and kept
going. Both open their store prompt at the launch, so every launch did this.
The store dialog sat thousands of pixels below its greyed tile.
Cause: `sizeTiles()` (app.js) measures each child of a tile. The prompt's
scrim is `position: absolute; inset: 0`, so its bottom is the tile's bottom.
Every pass asked for one more row, and the ResizeObserver on the taller scrim
started the next pass.
Fix: the scrim counts as its box's content height (`box.scrollHeight` plus
its padding). After: `SHOTS/after-dashboard-L.png`, the heights hold (640 px
at t0 and t+3 s, `h.log`). Test:
`test_view_web_procedure.py::test_w22_a_prompt_tile_keeps_its_size_and_shows_its_keys`
(fails before the fix: 14 rows, then 20).

### 2. Return does nothing in the Sample DB and store prompts (P1, Fixed a5a4e38)

Evidence: `dialogKey()` sent Return only to a key named exactly "Add" and
swallowed the entry's own Return (`preventDefault`). The Sample DB's keys are
"Add sample", "Add chip", "Add flake" and "Add material", and the store
prompts' keys are "New store" and "Open store". So in every real prompt,
Return did nothing.
Fix: Return presses "Add". Failing that, it presses the dialog key whose
command declares the focused entry as an input, a go key first: Sample ID
gives Add sample, New material gives Add material, Name gives New store,
Existing store file gives Open store (`keyTaking`). Verified live
(`f.log`: Return in New material added "hBN" and kept the dialog open;
Return in Sample ID added S-001). Test:
`test_view_web_ux_0808.py::test_return_in_a_prompt_entry_presses_the_key_that_takes_it`.
Return in a photo-path entry (a `file_open` widget, which has no entry
widget) did not press "Add photo…". **Fixed 482cbdb:** the prompt's Return
presses the path row's own key (`fileOpenKey`, `file-open-key`) first; the
prompt stays open. Test:
`test_view_web_ux_0808_rest.py::test_return_in_a_prompts_photo_path_presses_its_add_photo_key`.

### 3. The coach card has a second key called "Stop" (P1, Fixed e243cab)

Evidence: `SHOTS/d04-tutorial-step-L.png`. The tutorial card's buttons were
"Stop / Back / Next", on the same screen as the rail's red Stop. One of the
two stops nothing, and the operator learns from the bench that "Stop" means
the machine. Fix: "End tutorial"; the intro says "Escape ends it." Test:
`test_tutorials_take_focus_and_their_end_key_is_not_called_stop`.

### 4. A device page's store prompt hides its keys (P1, Fixed 904194a)

Evidence: `SHOTS/b10-page-transfer-map-L.png`. The card had `min-height: 22rem`
(352 px), but the prompt is about 490 px, so New store, Open store and Cancel
sat below the fold of the box's own scroller. The 700 px of empty sheet below
the card went unused.
Fix: the card is at least the prompt's height (`--dialog-need`, written by
`openDialog` and re-measured as the prompt changes, for example when a
refusal line appears). After: `SHOTS/after-tmap-store-L.png` (box 486/486,
no scroll). Same test as 1.

### 5. Link-lost words say "Hard reset it in Setup" (P2, Fixed a5a4e38)

### 6. Focus falls to `<body>` when a store prompt is answered (P1, Fixed a54f092)

Evidence: `e.log` ("TM after store Return: ... focus BODY"). The prompt opens
at the launch while focus is on the rail. When it closed, the focused entry
went back into a hidden section, and the dialog's return target was outside
the card. The next Tab started over at the skip link. The brief says focus
moves to the step's first control. Fix: when a step change closes a prompt
that held focus, `applyPhase` focuses the new step's first live control (or
the card). Test: `test_focus_lands_on_the_next_steps_first_control_after_a_prompt`
(fails before: BODY).

### 7. A prompt's dropdown chevron is far from its key (P2, Fixed f826a47)

Evidence: `SHOTS/e02b-sdb-new-sample-refused-L.png` (Material),
`SHOTS/b10-page-transfer-map-L.png` (Choose folder…). The prompt stretches its
rows, so `.select-key` ran the box's width while the select stays 10rem. The
chevron was drawn about 230 px to the right of its select. Fix:
`.dialog-box .select-key { align-self: flex-start; }`. Test:
`test_a_dropdown_in_a_prompt_keeps_its_chevron_on_its_key`.

### 8. The store prompt ignores `TRANSFER_STAGE_DATA_ROOT` (P1, Fixed 01b1b53; incident)

Evidence: `f.log`: "…/home/transfer-stage-user/transfer-stage-runs/stores/op@lab.test/sample_map.sqlite
already exists". The store prompt's default Folder is
`~/transfer-stage-runs/stores/<email>/` even in a SIM station with a temporary
data root. **Incident:** before this was found, the audit's Return-on-Name
runs (`e.js`) created `transfer_map.sqlite` and `sample_map.sqlite` under
`~/transfer-stage-runs/stores/op@lab.test/` on this PC. The audit did not
list or remove them (that folder is off limits); the lead should check and
delete them. Later runs typed a scratch folder first, with a guard that
aborts if the field holds anything else.
Proposal: derive the default store folder from the data root
(`TRANSFER_STAGE_DATA_ROOT`), or refuse a default under the home runs folder
while the data root is overridden, so tests and SIM audits cannot write
where the lab's real stores live.

### 9. Tutorials does not take focus (P2, Fixed e243cab)

move focus into their side window, and Escape returns it to their rail key

### 10. The tray keeps "Sample store not chosen" after the store is chosen (P1, Fixed b57846b)

Evidence: `SHOTS/e11-tmap-setup-full-L.png` and `f.log` (the tray line
persists after a Sample DB store was made and samples were added). The tray
shows the latest warning, so a warning that is no longer true stays on
screen as the station's headline. Proposal: the model publishes a "resolved"
event (or clears the attention) when a store is chosen, and the tray drops a
line whose condition has cleared. The rule belongs in `events`, not the view.
Fix: `events.info(..., resolves=TITLE)` names the warning an event ends
(`Event.resolves`, sent in `to_dict`). It also ends that title's dedupe
episode, so if the condition comes back it notifies again. The maps' store
choice (`_choose`) resolves `SAMPLE_STORE_NOT_CHOSEN` /
`TRIAL_STORE_NOT_CHOSEN` (now named in `events.py`). The page drops the
tray line when the resolving event has the same source (`resolvesTray`).
Tests: `test_view_web_ux_0808_open.py`
(`test_the_tray_drops_a_store_warning_once_a_store_is_chosen`, which fails
before the app.js change, and two model/event tests).

### 11. "New flake on ? · ?" (P1, Fixed 32ea437)

Evidence: `SHOTS/f02-sdb-new-flake-S.png`, `f.log`. Right after New chip, the
New flake prompt's title read "on ? · ?" and stayed so through a refused Add.
After a reload it read "on S-001 · C1" (`g.log`). The section title is built
in `SampleMap.schema` from the current pick. The page keeps the schema it
fetched, so the title is stale. An operator cannot confirm where the flake
is filed. Proposal: carry the parent ("S-001 · C1") in state and draw it as
a readonly line in the prompt, or have the page re-read the schema when the
phase changes.
Cause (confirmed): the page builds each card once, from the schema it
fetches in `addCard`, and never reads it again. The Sample DB's section
titles ("New chip on …", "New flake on …", "Pictures of …", "Trials on
this …") are built from the pick of the moment. Nothing is cached on the
server and the model's state is fresh, but the titles were not in the
state. Fix: a model whose titles move publishes them in its state
(`section_titles`, one per schema section; SampleMap does). The card
rewrites the titles that changed, in place, along with the prompt's
aria-label (`applyTitles`). A first version (dfd198a) re-read
`/api/schema` on a step change. That broke the W2-1 rule that the strip
and the steps follow state with no fetch, so 32ea437 replaced it. Tests:
`test_a_prompts_title_names_the_pick_made_after_the_page_loaded` (it read
"New tip on ?" before the fix) and
`test_the_sample_dbs_state_carries_its_titles_of_now`.
