## Findings

Format: severity, `file:line`, what, fix, status.

### S3

1. **S3, `src/views/web/static/styles.css:889` (and `.select` ~1973, `.input` ~1927, `.checkbox` 2391, `.switch`, `.slider-cap`, `.disc-key` 1403, `.mushroom` ~475)**
   No `forced-colors` handling. Keys are drawn with `border: 0` plus an
   inset `box-shadow` rim and a coloured lip; Windows High Contrast removes
   box shadows and recolours borders, so a key may reduce to a bare lip line
   and its label. The lab PC is Windows. Fix: an additive
   `@media (forced-colors: active)` giving each control class a
   `1px solid ButtonText` border (and `CanvasText` for the tick and cap).
   **Left**: unverifiable without a Windows High Contrast capture, and a blind
   border change shifts key heights. UNVERIFIED.
2. **S3, `src/views/web/static/index.html:9` (and `app.js:4120` `navigateTo`)**
   `<title>` is the static "Transfer stage" and no page is in the URL, so a
   screen-reader user or the browser history cannot tell Overview from a
   device page, and Back leaves the console. Fix: set `document.title` to
   "<page> - Transfer stage" in `navigateTo`, optionally `location.hash`.
   **Left**: a JS behaviour change (history entries would change what Back
   does), Ian's call.
3. **S3, `src/views/web/static/index.html:232`** The region picker's
   `<canvas>` had an `aria-label` but no role, so the name was not exposed
   (the plot canvases in `app.js:1702` do set `role="img"`). Fix: `role="img"`
   (the four number fields are the keyboard path). **Fixed.**
4. **S3, `src/views/web/static/styles.css:2391`, `:1403`** `.checkbox` and
   `.disc-key` are exactly 24 x 24 px, the WCAG 2.5.8 AA floor and no more.
   They sit inside labelled rows (the label is part of the target), so this
   passes. Fix if wanted: grow to 1.75rem. **Left**: a visible layout change
   to every Setup row; the bench scale does not enlarge them either.

### S4

5. **S4, `src/views/web/static/index.html:8`** No `color-scheme` meta; the
   stylesheet declares `color-scheme: light` on `:root`, but the meta stops
   form controls and the canvas flashing dark in a dark-preferring browser
   before the CSS loads. **Fixed** (`<meta name="color-scheme" content="light">`).
6. **S4, `src/views/web/static/styles.css:81`** Sheet keys, selects and fields
   are 36 px (`--hit-panel` 2.25rem): above WCAG 2.5.8's 24 px, below the
   44 px of 2.5.5 and Apple/Google guidance, for gloves. **Fixed for the
   people who need it** by the bench scale (44 px, opt in); the default is
   unchanged by design (density at a desk).
7. **S4, `src/views/web/static/styles.css:165`** There is no global
   `[hidden]` rule (the file says so); any element given an author `display`
   shows even with the `hidden` attribute. Today every case is handled
   per class (`.tutorial-panel[hidden]`, `.stop-hint[hidden]`), but the next
   component will trip it. Fix: `:where([hidden]) { display: none; }`
   (zero specificity, changes nothing that exists). **Left**: no current
   defect, and a global default can interact with the per-class rules; add
   it with a rendered pass.
8. **S4, `src/views/web/static/styles.css:821` and `:833`** The status dots
   now separate error by shape (a diamond, `:854`), but enabled and disabled
   are still two round dots told apart by colour alone (grey against trace,
   1.13:1); the energized ring only marks a device that is energized, not
   one that is merely enabled. Fix: a hollow ring for disabled. **Left**: the
   colours and the dot tests are pinned by the owner ruling (audit finding 5).
9. **S4, `src/views/web/static/styles.css:532`** The chord keycaps are
   11.5 px (`--t-kbd`), the one text under 12 px. They are `aria-hidden`
   and repeat the words "Stop: Ctrl+.". **Left**: decorative duplicate.

### Checked and clean (no finding)

Focus: one `:focus-visible` ink ring (`styles.css:136`); every
`outline: none` has a replacement (`.card`, `.card-open` via `:has`,
`.slider-range` via the cap, the stop via `.stop-ring:has(...)`).
Layers: drawers use `inert`, `aria-hidden` and `visibility` together
(`app.js:3945`, `4148`); modals are inert-backed. Live regions: polite and
assertive regions in `index.html`, `role=alert` only on the rail alerts,
gate error, tutorial note. Names: icon-only controls are labelled; visible
text is contained in every `aria-label` (2.5.3). Forms: labels, `type`,
`autocomplete`, `inputmode`, `spellcheck=false`, no blocked paste.
Motion: `prefers-reduced-motion` zeroes durations; no `transition: all`;
only `transform`, `visibility` and `box-shadow` transition. Typography: a
real ellipsis in copy, `text-wrap: balance` on headings, tabular figures on
readings and logs, `translate="no"` on device names. Headings descend
h1 (rail) to h2 (cards, drawers) to h3 (sections). Touch: `touch-action:
manipulation` on controls, `overscroll-behavior: contain` on every scroller.
Safety: the stop is never inert (`app.js:4140`).

## Bench scale (proposal 6)

`--font-size` already exists: a launch flag (`src/app.py:430`,
`theme.set_font_size`, `FONT_SIZE` points, clamped 8-28) served as the
`--font-size` CSS variable. That is the base the bench scale steps up from;
no second mechanism was invented.

- Setup shows a Display section (after the upkeep rows, before Station
  defaults) with a "Bench scale" On/Off key (a toggle, not a tick box: Setup
  has none, owner 2026-10-07) (`src/controller/setup.py:3490`). `set_bench_scale` (`setup.py:2247`) holds
  it for the session and remembers it where the store choice is remembered:
  a signed-in user's own settings, a Guest's the station's choices file
  (`user_config` key `bench_scale`, `src/controller/user_config.py:33`); it is
  re-read on every sign-in and switch (`setup.py` `_become`).
- The theme serves `--font-size-bench` = `theme.size(1)`, one step up the
  theme's own type scale (`src/views/theme.py:280`; 12 pt becomes 14 pt, and
  `--font-size 16` becomes 19 pt).
- The client sets `data-bench` on the root from `values.bench_scale`
  (`app.js:4854` `applyBenchScale`), then re-measures the tray and rail.
- The stylesheet (`styles.css:103`) points `--font-size` at the bench size
  and `--hit-panel` at `max(44px, 2.25rem)`; every sheet key, select, field
  and switch is sized from `--hit-panel`, and everything else follows the rem.

Not done: the 24 px checkbox and disclosure keys do not grow (finding 4); the
rail controls were already 44 px.
